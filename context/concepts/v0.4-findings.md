# v0.4 findings — the breaking window and the salvage map

Recorded at the 2026-08-31 workspace retrospective, from a full evaluation of the module at
v0.3.0. The strategy this serves is the coordinator's
`standards-lab/context/design/dsl-driven-services.md` (its §10 summarizes this note);
`v1.data.sql.query` and `v1.data.sql.migrate` in the roadmap cite it. These are session
inputs, not open strategy; the note decays as the sessions consume it.

## Breaking-window items (ride v0.4 because they are breaking or blast-radius-coupled)

1. **Error mapping moves inside `Session`/`Tx`.** `DB.QueryContext`, `DB.ExecContext`, and
   the three `Tx` methods (`session.go`, `tx.go`) return raw driver errors; only `Tx.Commit`
   maps. Every runner in `exec/` calls `s.Dialect().MapError(err)` by hand, and so do
   consumers touching `Session` directly (go-web-service `domain/organization/database.go`
   does it twice, for the advisory lock and the ancestor walk). Deleting `exec` deletes the
   only code that reliably maps — and native SQL increases direct session use. Mapping
   becomes a property of the seam; `MapError` becomes internal to it.
2. **One transaction-runner shape.** `ExecTx` (`tx.go:70–80`) has no `recover` (a panic in
   `fn` leaks an open transaction until the pool reaps it) and discards the rollback error
   (`_ = tx.Rollback()`), while `seed/seed.go:110–113` joins it — two helpers in one module
   with different failure semantics, and `migrate` arrives as a third. Pick one shape:
   recover, joined rollback errors, and reachable `sql.TxOptions` — `DB.Begin` hardcodes
   `BeginTx(ctx, nil)` while `operation/doc.go` and `design/layers.md` state the guard's
   split is "exact under serializable isolation": a documented guarantee with no code path.
3. **The `postgres` sub-module is provider-visible blast radius.** `postgres/dialect.go`
   implements `RenderReturning` against `ast.Writer` and the `ast` capability interfaces.
   Decide the re-home explicitly: `ReturningRenderer` and `Writer` have no purpose once
   statements are files; `Placeholder` must survive (the dynamic filter/sort/page fragment
   still renders binds); `Provider` (`dialect.go:6`) is a typed constant the base module never
   uses. And CI is structurally blind to pin breakage: the committed `go.work` resolves the
   base module locally, proven at tag `v0.3.0` where `postgres/go.mod` still pinned
   go-database v0.1.1 and imported a package that did not exist there — the tagged tree could
   not build standalone. Add `GOWORK=off` per-module build steps before v0.4 work begins.
4. **The request-error taxonomy is wrong.** `operation/query.go:39–42` wraps a user-supplied
   bad page number in `ast.ErrInvalidStatement`, so it arrives at the consumer classified as
   invalid SQL — indistinguishable from a programming defect — and go-web-service's matcher
   has no case for it, so it falls through to 500. `query` gets its own sentinel for "your
   directives are bad," alongside the surviving typed field/operator errors.
5. **The field contract carries types.** Filter values pass through as text for the engine to
   type from context, and `postgres.MapError` classifies only SQLSTATE class 23 — so
   `?version=abc` is a 22P02 `invalid_text_representation` → 500 on well-formed client input.
   The projection knows each field's name; it must know its type (or the layer must map
   22P02-class errors to the request-error sentinel). Settle before the vocabulary multiplies
   across four domains. Related: `ErrNotReady`/`ErrConnectionFailed` are unmatched at
   consumers — an outage answers 500 where 503 is truer; the sentinel taxonomy should make the
   distinction expressible.
6. **`Session` gains `PrepareContext`, and the fakes must support it.** Verify prepares every
   statement, but every scripted `driver.Conn` fake in the layer returns "prepare unsupported"
   (`exec/exec_test.go:53`, `database_test.go`) — prepare-based verification has no test
   harness, and consumers copying the fakes inherit the hole. Promote the scripted-driver
   harness and the duplicated stub dialect (`ast/dialects_test.go`,
   `operation/dialects_test.go`) into one shared internal test package with prepare support.
   Also worth deciding while `Session` breaks: it exports `ExecContext` although writes go
   through `*Tx` (the read seam carries a write method), and its name says connection scope,
   not SQL session.

## The salvage map (what survives into `query`, precisely)

Keep, verbatim or near-verbatim (~250 lines):

- `operation/errors.go` (36 lines) — `UnknownFieldError{Field, Use}`, `FieldUse`,
  `UnknownOperatorError`. The single most load-bearing file: the only thing keeping a
  user-supplied field name out of SQL text, and what consumers actually `errors.As` on.
- `operation/directives.go` (95 lines) — `Page`/`Sort`/`Op`/`Filter`/`Directives`: the
  10-operator vocabulary, the 1-based page contract, the request-shaped value.
- `operation/query.go:60–77, 129–156` — the key-tie-breaker rule (the key joins every ORDER
  BY so offset paging is stable), duplicate-field detection, select-list ordering.
- `exec/query.go:15, 74–97` — `Scan[T]` and `Query[T]`; `List`'s count-and-page-share-one-
  WHERE envelope survives as a shape fed by a SQL file.
- `exec/command.go:40–97` — `guardFailure`, the affected-rows→outcome mapping,
  `Identity{ID, Version}`, and the "guard owns the version column, rejects a caller
  assignment to it" rule (`operation/command.go:94–102`).

Rewrite, don't port:

- `lowerFilter` (`directives.go:62–95`) is written against `ast.Expression`/`ast.Predicate`;
  the lowering re-targets `(fragment string, args []any)` against the field→column map. The
  fragment renderer needed is ~40 lines — resist porting `ast/nodes.go` + `renderer.go`
  (437 lines) "just for the WHERE clause."

Do not port:

- `ast/*` (~1,220 lines) — the rendering machine.
- `operation/recursive.go` `RecursivePath` — one consumer (the org tree); exactly what a
  `.sql` file expresses better. Its "transformer decomposition" held seam in `layers.md` dies
  with it.
- `operation/fields.go` `Columns`/`Fields` — string-concat builders, dead under native SQL.
- `ast/compound.go` — only non-test caller is `RecursivePath`.

Salvage that isn't a package: the typed split between "your request is bad" and "this can't
run here" (`ast/errors.go`'s `ErrInvalidStatement` vs `UnsupportedFeatureError`) re-expressed
for `query`'s sentinels; the two-direction dialect capability pattern and divergence ledger
from `design/layers.md`.

## Adjacent defects to fix while the files are open

- `Config.Password` has no redaction — no `String()`, no `slog.LogValuer`; any `%+v`,
  `json.Marshal`, or `slog.Any("config", cfg)` leaks it. (The management surface's config
  rendering makes this load-bearing; the redaction contract itself is go-core's, per the
  startup task.)
- Wiring-defect convention contradicts itself in one module: `database.New` panics on nil
  conn/dialect; `postgres.New` panics on unfinalized config but errors on bad `Options`;
  `seed.New` errors on nil db/logger. Pick the panic-on-wiring rule and apply it.
- `session.go:20–22, 31–33` have a blank line between doc comment and func — `DB.QueryContext`
  and `DB.ExecContext` render undocumented in godoc.
- `seed.Runner` takes a bare `*sql.DB`, sitting outside the dialect, error taxonomy, and
  lifecycle wrapper; `migrate` is its structural twin (embed.FS + ordered steps + one
  transaction each) — share the runner or accept two mechanisms deliberately.
- `ast/dialects_test.go` and `operation/dialects_test.go` are two copies of one stub dialect
  (absorbed by the shared test package above).
- `README.md` still describes the module as "the `database` package at its root and `seed`
  beside it" — two releases stale; the release checklist gains a README check
  (`backlog.workspace-sweep` carries the org-wide instance of this).
